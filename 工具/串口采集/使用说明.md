# 电子秤串口采集

支持 `raw / net / g / g_avg` 和新版可选字段 `g_iir`、独立 `temp_c` 行、去皮与单位事件，以及温度异常和 HX711 超时提示。Windows 的 VS Code 终端、PowerShell 中默认显示固定面板，状态在原处刷新，不滚动打印数据。当前状态只分“载荷未标记 / 空载 / 标称载荷多少克”，温度自动记录，不必切换降温或回温模式。程序只接收串口数据，可独立在电脑运行。

## 带到笔记本

解压同目录的“电子秤采集器_分量程笔记本版_2026-11-26.zip”，或复制整个“串口采集”文件夹。保留全部文件，不要只复制一个入口脚本，也不要直接在压缩包内部运行。当前1 kg梁用`开始采集_1kg.cmd`，历史20 kg梁用`开始采集_20kg.cmd`。

先安装Python 3.10或更新版本，并勾选Add Python to PATH。以后双击对应量程的CMD，选实际串口即可。入口检查同一个Python中的pySerial 3.5，缺少时自动安装；首次安装需要联网，失败会停止并显示错误。已有正确依赖时不重复安装。

两个量程入口均可连续记录几小时，运行期间临时阻止Windows自动空闲睡眠，结束后恢复；显示器可以熄屏，但不要手动休眠、合盖或关闭窗口。CMD不依赖PowerShell的PS1执行策略，不需要管理员权限。结束后按回车只是关闭窗口，数据持续写盘，输入`q`会正常收尾。

Python入口分别为`采集_1kg.py`、`采集_20kg.py`，在VS Code终端执行也会自动检查依赖。旧`开始采集.cmd`和`开始长时间采集.cmd`先让你选量程，不再默认20 kg。新便携包仅包含采集运行文件，离线分析工具保留在仓库；`文件清单.json`记录包版本和各文件SHA256。

| 运行位置 | 1 kg保存目录 | 20 kg保存目录 |
| --- | --- | --- |
| 完整毕设仓库 | `实验数据/1kg称重梁/原始数据/串口采集/日期时间/` | `实验数据/原始数据/串口采集/日期时间/` |
| 笔记本单独解压或复制整个工具目录 | `脚本目录/采集数据/1kg/日期时间/` | `脚本目录/采集数据/20kg/日期时间/` |

保存位置根据脚本所在目录确定，与终端当前目录无关。分量程入口不接受`--output`或覆盖量程的`--meta`参数；需要换磁盘时移动整套工具即可。启动、固定面板和结束提示均显示保存位置。每次独立建目录，不覆盖旧记录。简明操作见[先看这里](先看这里_保存位置.md)。

版本来自你选择的入口，不是自动识别金属梁。当前1 kg期望系数736.8698计数/g、固件`scale1kg_20261126`；20 kg历史期望系数178.20计数/g。收到不一致的启动字段时提示并写`profile_mismatch`事件，原始数据继续保留。只核对已收到的字段，未收到参数时不假装已验证；重新标定后更新`capture_profiles.py`中的期望值。入口不烧录，也不在电脑端重算重量。

## 实验时如何使用

1. PCB供电稳定后，将**PA9（TX）接USB转串口模块的RX，GND接GND**；仅采集不需要接PA10或转串口模块的TX。GPIO侧使用3.3 V逻辑电平，供电5 V与串口逻辑电平是两回事。转串口模块的VCC不必接到已供电PCB。
2. 关闭串口助手的端口，避免占用。准备记录完整开机信息时，先开始采集，再按核心板复位键；开机自动去皮时秤盘保持空载。温漂正式采集过程中不随意复位或去皮。
3. 双击`开始采集_1kg.cmd`（历史20 kg用`开始采集_20kg.cmd`），按提示输入实际串口序号；脚本会实际测试`py -3`和`python`，使用真正能启动的Python。串口变号时重新选择即可。默认115200、8数据位、无校验、1停止位。
4. 固定面板每秒更新载荷、时长、重量、温度、接收状态和保存位置。下方输入命令后回车；刷新不会清掉正在输入的文字。**输入 q 或按 Ctrl+C 停止并保存**，不要直接关窗口。关闭合盖休眠，避免移动时扯到 USB / 拓展坞；程序不设置时长时持续采集。

运行两个Python量程入口也会自动处理依赖；直接运行底层`collect_serial.py`则需自行安装。手动安装命令为：

```powershell
py -3 -m pip install -r requirements.txt
```

如果`py`启动器报“没有安装Python”但`python --version`正常，可使用`python 采集_1kg.py`；双击入口会自动回退。另一台电脑需独立安装依赖。

## 采集过程中标记动作

开始后，在同一个黑色窗口输入下面命令并回车。串口接收不会停止。电脑记录的是你输入命令的时刻，通常晚于真实动作；分析时还要结合备注与视频/照片。

| 输入 | 用途 |
| --- | --- |
| `500` / `上500` / `上 500` | 当前标称总载荷设为500 g；100、200及其他正数同理，不累加 |
| `下` / `0` / `卸载` | 标记全部卸下砝码，当前为空载 |
| `s` | 标记稳定段开始；载荷标记与稳定标记分开 |
| `n 移到室外` | 带时间戳的备注，原始采集不中断 |
| `t` / `r` | 记录自己已手动去皮 / 复位，不发送控制指令 |
| `q` | 结束采集并保存摘要 |
| `c base 室温基线开始` | 基线开始 |
| `c cold 加入密封冰杯` | 加入冷源 |
| `c close 关好保温袋` | 关袋/关盖 |
| `c remove 取走冰杯` | 移除冷源并降温过程结束 |
| `c load 500 中心` | 放置标称500 g，最后一个词是备注 |
| `c unload 卸载完成` | 移除载荷 |
| `c stable 观察温度稳定` | 稳定段开始，与“放置完成”分开 |
| `c tare 空载去皮` | 记录人工去皮动作 |
| `c touch 碰到连接线` | 意外碰触 |
| `c fault 发现结露` | 异常 |
| `c note 其他说明` | 一般备注 |
| `h` | 再显示命令表 |

启动时载荷为“未标记”，不自动当成空载。实际空载后输入 `0`；放好砝码再输入 `500`。换到200 g时输入 `200`，表示当前总载荷200 g。`下500`也表示卸载到空载；部分移除砝码时直接输入剩余总载荷。

事件也可写中文类别，例如`c 加入冷源`或`c 放载荷 500 中心`。事件写入`events.csv`，包含会话号、电脑标记时刻、持续秒、最近串口seq、事件类别、标称载荷、备注和来源。不要把“放好载荷”和“稳定段开始”合并成同一时刻。

串口长时间无数据、没有有效重量、温度失效或过旧、HX711饱和/超时、文件保存异常会提示。同一持续异常不反复弹出，恢复后再提示。正常负数和重量波动照常记录。旧重量、旧温度在面板注明旧值，不能当成实时测量。终端不支持固定面板时自动使用安静文本模式，只有操作、异常和结束摘要会追加输出；可主动加 `--plain` 选择此模式。

## 保存了什么

每次在上表中所选量程的目录下创建日期时间文件夹，保留旧数据，不覆盖。20 kg历史目录保持原位，1 kg独立保存。

| 文件 | 用途 |
| --- | --- |
| `serial.txt` | 便于直接阅读：每行带本地接收时间、时区、序号；含采集器开始、停止、无数据、健康警告和人工事件 |
| `records.csv` | Excel或Python分析：每条固件输出一行，包含原文、解析字段、电脑接收时间与持续秒数 |
| `received.bin` | 实际收到的全部原始字节，包含原始换行、乱码或断线前半行；用于复核 |
| `events.csv` | 不中断采集的动作标记；动作类别、标称载荷、备注、电脑标记时间、最近串口seq |
| `session.json` | 端口、串口参数、场次信息、阈值、起止时间、结束原因、计数、脚本哈希和结束摘要 |
| `summary.json` | 机器可读结束摘要：有效/异常行数、有效温度范围、温度错误段、数据中断和文件清单 |
| `summary.md` | 人工阅读的结束摘要及分析入口 |

时间戳是**电脑收到完整行时的时间**，精确显示到毫秒并带时区；不代表HX711真实采样时刻。`elapsed_s`用电脑单调时钟计时，避免修改系统时间使持续时间倒退。电脑时钟校正仍会反映在本地时间列里。

CSV中的`temp_c`只在本行实际含温度时填写，`raw/net/g/g_avg`只在本行实际发送时填写。`latest_temp_c`是此前最近一条有效温度，附`latest_temp_received_local`、`latest_temp_seq`、`temp_age_s`；它是便于后期对齐的快照，**不是与重量同时采样的温度**。`temp_state=unknown`表示尚未收到有效温度，`ok`表示最近一次温度结果有效，`error/invalid`表示随后收到错误或无效温度。即使有旧温度也需检查年龄和状态，不直接当成当前梁温。无新温度时年龄会增长。

新版本在 `records.csv` 末尾追加 `manual_load_state`、`reference_mass_g`、`last_event_id`。分别表示人工标记的载荷状态（unknown / loaded / unloaded）、标称总载荷（g）、本行之前最后一个事件号。初始载荷为空，卸载后为0；这些字段是人工备注，不是秤的测量值，也不自动证明已经稳定。已有列顺序保留，旧会话不改动。

仓库内的`summarize_calibration.py 会话目录 --output 分析目录 --current-k 736.8698`可分析当前1 kg版本；历史默认值178.20仅适用于旧20 kg配置。它保留原事件时刻，并结合宽载荷区间连续读数定位动作，排除加载后10秒和下一换载前3秒，段尾最多30秒，至少60条有效记录。200/500 g拟合，其他载荷不参与系数估计。分析输出必须在原始会话之外，拟合不会自动写入固件。`fit_frozen_calibration.py`处理本轮已冻结的原始计数窗口，详见11月26日阶段记录。便携包不含这些离线工具，数据带回仓库后分析。

`g_avg` 是 5 点滑动平均，`g_iir` 是对同一批 `net` 输入独立计算的一阶 IIR 结果，单位均为 g。旧固件未输出 `g_iir` 时，该列留空。

断线前半行或异常长行片段标记为`record_type=partial`、`line_complete=0`，不按有效测量解析。未知消息和启动提示照样保存。脚本不做均值、删除异常点或补偿，也不推断未知去皮偏移量。

`raw`等于−8388608或8388607时标为`weight_saturated`，`raw=... tare=invalid`标为`weight_tare_invalid`；两者都不计入有效重量行。温度错误不进入有效温度范围统计。有称重但从未有效测温、最近温度错误或超过年龄阈值时，窗口显示健康提示并写入`temperature_stale`事件；恢复后写`temperature_resumed`。连续无串口数据会写`data_gap`，恢复时写`data_resumed`，不补造缺失行。

文件每秒刷新并请求落盘，正常停止时再次刷新。突然断电、磁盘故障或强制杀进程仍可能损失最近数据；`session.json`若仍为`running`，表示未经过正常结束流程。断线或写文件错误会停止并报告，不自动接另一个端口，也不假装采集连续；重新启动生成新会话。

## 可选命令

在本目录终端执行：

```powershell
# 只查看端口，不打开
py -3 采集_1kg.py --list

# 指定端口并完整记录场次条件，持续采集
py -3 采集_1kg.py --port COM3 --hours 2 `
  --label "空载冰杯预实验" `
  --experiment-type "空载降温自然回温" `
  --assembly-version "实际板版号待填" `
  --firmware-version "实际固件待填" `
  --module-id "实际HX711编号待填" `
  --sensor-id "实际DS18B20编号待填" `
  --probe-position "梁侧实际位置待填" `
  --power-supply "实测5V/3.3V待填" `
  --reference-mass "空载" `
  --thermal-source "密封冰杯，保温袋外控制板" `
  --note "不重复复位或去皮"

# 连续6小时后自动停止
py -3 采集_1kg.py --port COM3 --hours 6 --label "温漂预试验"

# 只查看保存位置，不开串口
py -3 采集_1kg.py --show-path

# 采集60秒，仍在1 kg独立目录保存
py -3 采集_1kg.py --port COM3 --seconds 60

# 记录固件文件哈希，允许附加KEY=VALUE，调整温度/无数据提示阈值
py -3 采集_1kg.py --port COM3 --firmware-file "实际固件文件.hex" `
  --meta "bench=bench-1" --temp-stale-seconds 5 --data-stale-seconds 30
```

场次字段只记录用户输入，未指定时在JSON中保留空字符串，不会自动猜测。不要把“待填”字样直接用于正式实验；根据实测板版号、固件、探头位置和万用表读数填写。更换砝码及冷热源时输入事件命令。无桌面控制台或自动化测试可用`--no-events`关闭事件输入，串口采集与文件保存不受影响。端口号以实际列表为准。

遇到30秒无数据提示时，检查接线、供电与端口是否正确；程序仍在等待。端口无法打开时先关闭串口助手端口，再核对USB转串口驱动。不要通过反复复位或去皮掩盖温漂。

## 验证范围

测试命令：`python -m unittest discover -s . -p "test_*.py" -v`。2026-11-12在Python 3.12.10、pySerial 3.5下通过10项自动测试。测试使用临时目录与明确标注的模拟数据，覆盖半行拼接、温度状态/年龄、原始字节、事件命令与别名、主标称载荷解析、场次元数据与空字段、结束摘要、错误温区统计、断线与磁盘打开失败、旧CSV列兼容、不覆盖旧会话及pySerial内存回环；不写入实验原始数据目录。模拟测试不等于真实称重或温度结果。

2026-11-12上午枚举到COM5/6/8/9为蓝牙串行端口，COM12为其他USB串行设备，未见11月9日使用的CH340 COM4。下午用户接入传感器后新增COM11 CH340。首次0字节连接在用户确认串口断开后已按要求删除；重新连接后的60秒检查收到275行有效重量和69行有效温度，温度26.43～26.56℃、无温度/设备错误。随后10分钟桌面空载测试也完整保存，但raw前4分钟下降明显，后段尚未证明完全稳定，因此只确认采集链路可用，不能直接开始冰杯正式实验。详细数据见当天“桌面空载连接检查与稳定性测试记录”。

串口接口与端口枚举按[pySerial API](https://pyserial.readthedocs.io/en/latest/pyserial_api.html)及[端口枚举文档](https://pyserial.readthedocs.io/en/latest/tools.html#serial-tools-list-ports)实现。
