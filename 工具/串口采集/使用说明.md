# 电子秤串口采集

支持 `raw / net / g / g_avg` 和新版可选字段 `g_iir`、独立 `temp_c` 行、去皮与单位事件，以及温度异常和 HX711 超时提示。采集过程中可输入放冷源、放砝码、去皮等事件标记。程序持续显示温度和称重状态，结束时生成摘要。程序只接收串口数据，可独立在电脑运行。

## 实验时如何使用

1. PCB供电稳定后，将**PA9（TX）接USB转串口模块的RX，GND接GND**；仅采集不需要接PA10或转串口模块的TX。GPIO侧使用3.3 V逻辑电平，供电5 V与串口逻辑电平是两回事。转串口模块的VCC不必接到已供电PCB。
2. 关闭串口助手的端口，避免占用。准备记录完整开机信息时，先开始采集，再按核心板复位键；开机自动去皮时秤盘保持空载。温漂正式采集过程中不随意复位或去皮。
3. 双击同目录的`开始采集.cmd`，按提示输入串口序号；脚本会实际测试`py -3`和`python`，使用真正能启动的Python。串口变号时重新选择即可。默认115200、8数据位、无校验、1停止位。
4. 软件每5秒显示保存目录、时长、行数、有效重量、最近温度及年龄、错误数、接收间隔。原始数据持续写文件。**Ctrl+C停止**，不要直接关窗口。关闭休眠，长时间试验接好电脑电源；程序不设置时长时持续采集。

首次使用的电脑需安装Python 3（建议3.10及以上），然后在本目录终端执行：

```powershell
py -3 -m pip install -r requirements.txt
```

如果`py`启动器报“没有安装Python”但`python --version`正常，可直接使用`python collect_serial.py`；双击入口会自动回退。另一台电脑需独立安装依赖。

## 采集过程中标记动作

开始后，在同一个黑色窗口输入下面命令并回车。串口接收不会停止。电脑记录的是你输入命令的时刻，通常晚于真实动作；分析时还要结合备注与视频/照片。

| 输入 | 用途 |
| --- | --- |
| `c base 室温基线开始` | 基线开始 |
| `c cold 加入密封冰杯` | 加入冷源 |
| `c close 关好保温袋` | 关袋/关盖 |
| `c remove 取走冰杯` | 移除冷源并降温过程结束 |
| `c load 500 中心` | 放置标称500 g，最后一个词是备注 |
| `c unload 卸载完成` | 移除载荷 |
| `c stable 观察温度稳定` | 稳定段开始，与“放置完成”分开 |
| `c tare 空载去皮` | 记录人工去皮动作 |
| `c touch 碰到连接线` | 意外碰触 |
| `c fault 发现结露` | 异常 |
| `c note 其他说明` | 一般备注 |
| `h` | 再显示命令表 |

事件也可写中文类别，例如`c 加入冷源`或`c 放载荷 500 中心`。事件写入`events.csv`，包含会话号、电脑标记时刻、持续秒、最近串口seq、事件类别、标称载荷、备注和来源。不要把“放好载荷”和“稳定段开始”合并成同一时刻。

## 保存了什么

每次在仓库`实验数据/原始数据/串口采集/`下创建以日期时间命名的新目录，保留旧数据，不覆盖。

| 文件 | 用途 |
| --- | --- |
| `serial.txt` | 便于直接阅读：每行带本地接收时间、时区、序号；含采集器开始、停止、无数据、健康警告和人工事件 |
| `records.csv` | Excel或Python分析：每条固件输出一行，包含原文、解析字段、电脑接收时间与持续秒数 |
| `received.bin` | 实际收到的全部原始字节，包含原始换行、乱码或断线前半行；用于复核 |
| `events.csv` | 不中断采集的动作标记；动作类别、标称载荷、备注、电脑标记时间、最近串口seq |
| `session.json` | 端口、串口参数、场次信息、阈值、起止时间、结束原因、计数、脚本哈希和结束摘要 |
| `summary.json` | 机器可读结束摘要：有效/异常行数、有效温度范围、温度错误段、数据中断和文件清单 |
| `summary.md` | 人工阅读的结束摘要及分析入口 |

时间戳是**电脑收到完整行时的时间**，精确显示到毫秒并带时区；不代表HX711真实采样时刻。`elapsed_s`用电脑单调时钟计时，避免修改系统时间使持续时间倒退。电脑时钟校正仍会反映在本地时间列里。

CSV中的`temp_c`只在本行实际含温度时填写，`raw/net/g/g_avg`只在本行实际发送时填写。`latest_temp_c`是此前最近一条有效温度，附`latest_temp_received_local`、`latest_temp_seq`、`temp_age_s`；它是便于后期对齐的快照，**不是与重量同时采样的温度**。`temp_state=unknown`表示尚未收到有效温度，`ok`表示最近一次温度结果有效，`error/invalid`表示随后收到错误或无效温度。即使有旧温度也需检查年龄和状态，不直接当成当前梁温。无新温度时年龄会增长。

`g_avg` 是 5 点滑动平均，`g_iir` 是对同一批 `net` 输入独立计算的一阶 IIR 结果，单位均为 g。旧固件未输出 `g_iir` 时，该列留空。

断线前半行或异常长行片段标记为`record_type=partial`、`line_complete=0`，不按有效测量解析。未知消息和启动提示照样保存。脚本不做均值、删除异常点或补偿，也不推断未知去皮偏移量。

`raw`等于−8388608或8388607时标为`weight_saturated`，`raw=... tare=invalid`标为`weight_tare_invalid`；两者都不计入有效重量行。温度错误不进入有效温度范围统计。有称重但从未有效测温、最近温度错误或超过年龄阈值时，窗口显示健康提示并写入`temperature_stale`事件；恢复后写`temperature_resumed`。连续无串口数据会写`data_gap`，恢复时写`data_resumed`，不补造缺失行。

文件每秒刷新并请求落盘，正常停止时再次刷新。突然断电、磁盘故障或强制杀进程仍可能损失最近数据；`session.json`若仍为`running`，表示未经过正常结束流程。断线或写文件错误会停止并报告，不自动接另一个端口，也不假装采集连续；重新启动生成新会话。

## 可选命令

在本目录终端执行：

```powershell
# 只查看端口，不打开
py -3 collect_serial.py --list

# 指定端口并完整记录场次条件，持续采集
py -3 collect_serial.py --port COM3 --hours 2 `
  --label "空载冰杯预实验" `
  --experiment-type "空载降温自然回温" `
  --assembly-version "实际板版号待填" `
  --firmware-version "实际固件待填" `
  --module-id "实际HX711编号待填" `
  --sensor-id "实际DS18B20编号待填" `
  --probe-position "梁侧实际位置待填" `
  --power-supply "实测5V/3.3V待填" `
  --reference-mass "空载" `
  --thermal-source "密封冰杯，保温袋外控制板" `
  --note "不重复复位或去皮"

# 连续6小时后自动停止
py -3 collect_serial.py --port COM3 --hours 6 --label "温漂预试验"

# 指定保存目录或采集60秒
py -3 collect_serial.py --port COM3 --seconds 60 --output "D:\称重数据"

# 记录固件文件哈希，允许附加KEY=VALUE，调整温度/无数据提示阈值
py -3 collect_serial.py --port COM3 --firmware-file ".\hx711test\MDK-ARM\Objects\hx711test.axf" `
  --meta "bench=bench-1" --temp-stale-seconds 5 --data-stale-seconds 30
```

场次字段只记录用户输入，未指定时在JSON中保留空字符串，不会自动猜测。不要把“待填”字样直接用于正式实验；根据实测板版号、固件、探头位置和万用表读数填写。更换砝码及冷热源时输入事件命令。无桌面控制台或自动化测试可用`--no-events`关闭事件输入，串口采集与文件保存不受影响。端口号以实际列表为准。

遇到30秒无数据提示时，检查接线、供电与端口是否正确；程序仍在等待。端口无法打开时先关闭串口助手端口，再核对USB转串口驱动。不要通过反复复位或去皮掩盖温漂。

## 验证范围

测试命令：`python -m unittest discover -s . -p "test_*.py" -v`。2026-11-12在Python 3.12.10、pySerial 3.5下通过10项自动测试。测试使用临时目录与明确标注的模拟数据，覆盖半行拼接、温度状态/年龄、原始字节、事件命令与别名、主标称载荷解析、场次元数据与空字段、结束摘要、错误温区统计、断线与磁盘打开失败、旧CSV列兼容、不覆盖旧会话及pySerial内存回环；不写入实验原始数据目录。模拟测试不等于真实称重或温度结果。

2026-11-12上午枚举到COM5/6/8/9为蓝牙串行端口，COM12为其他USB串行设备，未见11月9日使用的CH340 COM4。下午用户接入传感器后新增COM11 CH340。首次0字节连接在用户确认串口断开后已按要求删除；重新连接后的60秒检查收到275行有效重量和69行有效温度，温度26.43～26.56℃、无温度/设备错误。随后10分钟桌面空载测试也完整保存，但raw前4分钟下降明显，后段尚未证明完全稳定，因此只确认采集链路可用，不能直接开始冰杯正式实验。详细数据见当天“桌面空载连接检查与稳定性测试记录”。

串口接口与端口枚举按[pySerial API](https://pyserial.readthedocs.io/en/latest/pyserial_api.html)及[端口枚举文档](https://pyserial.readthedocs.io/en/latest/tools.html#serial-tools-list-ports)实现。
